Overview

Complete blood counts are one of the most common lab tests. Automating the detection of blood cells in microscope images is a classic computer-vision problem: red blood cells are numerous and overlap heavily, white blood cells are large but rare (usually one per image), and platelets are tiny and easy to miss.

Your task is object detection: for every test image, output bounding boxes with a class label and a confidence score. Any approach is allowed (Faster R-CNN, YOLO, DETR, classical CV…), as long as you train only on the provided data.

This is a prediction-only competition. You never upload code. You upload an encrypted predictions file, and a GitHub Action decrypts and scores it against labels that are stored only in repository secrets.

How it works

  1. Train on train and tune on val, both labelled.
  2. Predict boxes for the 72 unlabelled test images.
  3. Encrypt with the repo's public key and open a PR.
  4. The bot scores it, updates the leaderboard, comments your score and closes the PR.

Starting points

  • starter/baseline_fasterrcnn.py: torchvision Faster R-CNN that trains and writes a valid submission
  • scoring/score_submission.py --split val: the official metric, run locally on validation
  • scoring/validate_submission.py: checks the format before you encrypt

Image noise

About 90% of images in every split carry 1–2 random corruptions: Gaussian noise, salt & pepper dots (easy to mistake for platelets), blur, heavy JPEG compression, or colour/brightness/contrast jitter. Only pixels changed, never geometry, so every box is still exact. Denoising, augmentation and robust training are all fair game.

Coordinates are in pixels with the origin at the top-left corner; xmax/ymax are exclusive edges. Note that the original BCCD annotations are known to be incomplete, with some RBCs left unlabelled. Treat the labels as noisy.

Evaluation: mAP@0.5

For each class, all your boxes across the test set are sorted by score. A box is a true positive if its IoU with a not-yet-matched ground-truth box of the same class in the same image is ≥ 0.5; otherwise it is a false positive. AP is the area under the precision–recall curve (all-point interpolation, PASCAL VOC style).

mAP@0.5 is the unweighted mean of AP over RBC, WBC and Platelets, so the rare classes count as much as RBCs. Ties on the leaderboard share a rank; ordering within a tie is by earliest submission.

Submission format

image_id,label,score,xmin,ymin,xmax,ymax

bccd_0002,WBC,0.99,201,150,330,281

  • One row per predicted box. image_id must be one of test_images.csv.
  • label ∈ {RBC, WBC, Platelets}; score ∈ [0, 1]; xmax > xmin, ymax > ymin.
  • Up to 300 boxes per image. Boxes are clipped to the image.

Submit

  1. Fork the repository and clone your fork.
  2. Predict the test set and save predictions.csv in the format above, then check it: 
    python scoring/validate_submission.py predictions.csv
  3. Encrypt it with the repository's public key: 
    pip install cryptography pandas numpy
python encryption/encrypt.py predictions.csv encryption/public_key.pem predictions.csv.enc
  4. Add exactly two files in a new folder (team and run id: letters, digits, _ - .): 
    submissions/inbox/<team>/<run_id>/predictions.csv.enc
submissions/inbox/<team>/<run_id>/metadata.json
    {
  "team": "my_team",
  "run_id": "frcnn_v1",
  "author_type": "human",
  "model": "Faster R-CNN R50-FPN",
  "notes": "640px, hflip+vflip aug, 30 epochs"
}
    author_type is one of human, llm, hybrid. team/run_id must match the folder names.
  5. Open a Pull Request to main. Within a couple of minutes the bot comments your score and rank and closes the PR. If something is wrong it comments the reason; push a fix to the same PR to re-run.

Never commit the plain predictions.csv. Only the encrypted file is accepted.

Rules

  • One scored submission per team and per GitHub account. Validate on val first.
  • No external labelled blood-cell data, and in particular no use of the original BCCD annotations or images to identify test labels. ImageNet/COCO pretrained backbones are allowed; say so in notes.
  • No hand-labelling of test images.
  • Report honestly whether the solution was written by a human, an LLM, or both (author_type).
  • Organizers may remove entries that break the rules.
Data: BCCD Dataset (MIT licence). Scoring runs in GitHub Actions; test labels and the decryption key exist only as repository secrets.
